# 河道主动巡护系统云端使用说明

## 1. 系统访问地址

电脑端：

<https://scholarships-columbus-landscape-begins.trycloudflare.com/>

移动端：

<https://scholarships-columbus-landscape-begins.trycloudflare.com/mobile/>

电脑和手机可处于不同网络，通过浏览器直接访问。建议使用最新版 Chrome、Edge 或 Safari。

> 当前地址由 Cloudflare Quick Tunnel 提供，属于临时 HTTPS 地址。Cloudflare 隧道重启后地址可能变化；若页面无法打开，请联系管理员获取最新地址。

## 2. 登录系统

1. 打开电脑端或移动端地址。
2. 在登录页面输入管理员分配的账号和密码。
3. 登录成功后进入系统；电脑端和移动端使用同一服务器数据库。
4. 关闭浏览器后再次访问，需要重新登录。

请勿向无关人员透露系统账号、密码以及包含现场证据的图片。

## 3. 电脑端使用流程

### 3.1 图片识别

1. 进入“图片识别”。
2. 选择现场河道图片。
3. 自定义填写河段名称。
4. 点击“识别并生成建议”。
5. 查看漂浮物数量、置信度、检测框图片和预警结果。

系统按识别出的漂浮物数量预警：

- 1～3 个：黄色预警；
- 4～7 个：橙色预警；
- 8 个及以上：红色预警；
- 0 个：不创建预警事件。

### 3.2 摄像头巡护

- “浏览器摄像头”使用当前电脑的摄像头，首次使用时需要允许浏览器摄像头权限。
- “OpenCV / RTSP”由阿里云服务器读取视频源，只能使用服务器能够访问的 USB 设备、视频文件或 RTSP 地址。
- 本地电脑的 USB 摄像头不能通过服务器端的 OpenCV 编号 `0` 直接访问；远程电脑摄像头应使用“浏览器摄像头”。

### 3.3 事件台账

识别到漂浮物后，系统自动创建事件台账。事件按照以下顺序处理：

```text
待确认 → 已派单 → 处理中 → 已处理 → 复核通过 → 已归档
```

派单时填写处理人员，标记“已处理”时填写清理说明。事件详情中可查看原图、检测框图、处理记录和复核结果。

## 4. 移动端使用流程

1. 使用手机浏览器打开移动端地址并登录。
2. 在“巡查”页面拍照，或从手机相册选择河道图片。
3. 填写河段名称并提交识别。
4. 在“事件”页面查看服务器事件台账，并进行派单、处理、复核、归档或删除。
5. 在“设置”页面查看当前服务器、检查连接或退出登录。

移动端固定使用当前 HTTPS 页面所在的服务器，不需要手动填写 API 地址。登录、事件台账和证据图片均来自同一个云端数据库。

## 5. 复核与归档

1. 事件进入“已处理”后，上传清理完成后的现场图片。
2. 模型重新识别复核图片，并显示“通过/未通过”、漂浮物数量、风险等级和置信度。
3. 未检测到漂浮物时，才可以确认复核通过并归档。
4. 如果仍检测到漂浮物，应继续清理并重新上传复核图片。

## 6. 常见问题

### 页面无法打开

Cloudflare 临时隧道可能停止或地址已经变化。服务器管理员可执行：

```bash
grep -Eo 'https://[-a-z0-9]+\.trycloudflare\.com' /var/log/river-patrol-tunnel.log | tail -n 1
```

### 登录后移动端没有事件数据

关闭手机中原来的系统标签页，再从本说明中的移动端 HTTPS 地址重新打开并登录。不要通过公网 HTTP IP 打开移动端。

### 手机不能调用摄像头

确认使用的是 `https://` 地址，并在浏览器权限设置中允许该站点使用摄像头。也可点击图片选择区域，从相册上传图片。

### 图片上传或事件处理较慢

公网访问速度受手机网络和 Cloudflare 临时隧道影响。建议使用稳定的 Wi-Fi/5G，并避免上传过大的原始图片；移动端会在上传前自动压缩大图。

## 7. 管理员检查命令

在阿里云服务器执行：

```bash
cd /opt/river-patrol
docker compose -f compose.ip.yaml ps
curl http://127.0.0.1/health
docker compose -f compose.ip.yaml logs --tail=100
```

服务器业务数据位于 `/opt/river-patrol/runtime/`，其中包含 SQLite 数据库和上传图片。更新系统前应先备份该目录。
